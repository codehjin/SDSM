### 2-3. N5 저장 알림

`DuplicateImportHelper.SaveToast(BulkSaveResult)` → 7개 분류군 `SaveExecuted` 가 `GB.SaveMessage` 대신 이것을 보낸다.

| 결과 | 알림 |
|---|---|
| 바꾸거나 건너뛴 것이 없음(같은 기록 없음 · 또는 [추가]만) | '자료가 저장되었습니다.'(종전 `GB.SaveMessage`) |
| 저장 + 바꿈 = 0 | **'저장한 자료가 없습니다(모두 건너뜀)'** |
| 그 밖 | **'저장 n · 바꿈 n · 건너뜀 n건'** (저장 = 새로 저장 + 같은 기록이 있는데 추가) |

- 건수 단위는 어류·저서·수질·서식수변 = 기록, 관찰형 = 행(같은 기록 처리 결과 창과 같다).
- 저장 이력(`SavedFileInfo`)은 종전 규칙 그대로(저장 + 바꿈 > 0 일 때만).
- 알림 색은 보통(파란) 알림 — 사용자가 고른 결과라 오류(빨간)로 두지 않았다.
- 식생·식생환경·식물상은 건너뛰기·바꾸기가 없어 늘 전부 저장 → 종전 알림 그대로다.

### 2-4. 문제 4 남은 것 — 저서 환경값 원값

**찾은 것: 반올림이 두 군데였다**
1. 검수(`DataValidation`, 지시의 796행 부근): 수폭·하폭·수심·유속·기온·수온 `Math.Round(d, 1)`.
2. **가져오기**(`DataTableToModels` 411~416행): 셀 값을 `GetResultValueAsString(셀 표시 형식)` 으로 읽는데, 2026-03 양식의 34~39행 셀 형식이 `0.0_);[Red]\(0.0\)` 이다 → 0.45 가 글자 '0.5' 로, 0.123 이 '0.1' 로 읽힌다. 1만 고치면 원값이 들어가지 않는다(시험 파일로 확인 — 표시 형식 '0.5' · 일반 형식 '0.45').
   → 이 6칸만 `CellValueFormat.GeneralFormat` 으로 읽는다. 다른 칸 읽는 방식은 그대로.

**1007행 부근의 정체** — 환경값이 아니라 **종 행 개체수·오탁치(s)** 의 `Math.Round(d, 1)` 이었다.
- 개체수는 측정값이고, 지수(DI·H′·R1·J′·BMI)는 `GetSpeciesData` 에서 읽은 같은 값(반올림 전)으로 계산된다 → 종 행만 1자리로 깎이면 DB 의 지수와 종 행 값이 어긋난다(예: 2.25 로 계산하고 종 행은 2.3). 같은 원칙으로 반올림을 뺐다(읽는 방식은 그대로 — 지수 입력이 바뀌지 않게).
- 오탁치는 종목록 값이라 게시 DB 전부 1자리 이하(차이 0건)지만 같은 줄이라 같이 원값으로 둔다.
- ⚠ 개체수 칸 일부(양식 `#,##0.0` 형식 셀)는 가져올 때부터 1자리 글자로 읽힌다(3.7037037 → '3.7'). 지수도 그 값으로 계산되므로 이번에는 바꾸지 않았다(바꾸면 지수 입력이 바뀜 — 확인 필요 ③). → §13 에서 일반 형식으로 읽게 고침(§19-5 2026-10-21 고침).
