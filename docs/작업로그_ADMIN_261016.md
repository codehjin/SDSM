### 3-3. 발주처 배포 DB 에 적용하는 형태 (방안 2 기준)

| 형태 | 사용자가 하는 일 | 비고 |
|---|---|---|
| (가) SQL 스크립트 | DB 백업 → DB Browser for SQLite 등으로 스크립트 실행 → 마지막 줄 결과 838 확인 | 가장 단순·투명. 앱 재배포 불필요. SQLite 도구가 있어야 함 |
| (나) 별도 도구 (`tools\` 콘솔) | `도구.exe <DB경로> <최종본폴더>` → 미리보기 → `--apply` 시 자동 백업·트랜잭션 적용 | 관리자 변환 코드를 그대로 써서 매칭(이번 하네스와 같은 방식) |

SQL 형태 예시(형태만 — 실제 838줄은 결정 후 미리보기 목록에서 생성):

```sql
BEGIN;
UPDATE Mammal SET ObservationSite = '하천'
 WHERE MammalId = 271 AND ObservationSite IS NULL
   AND YearChsu = '2024반기1차' AND SurveyDate = '2024-01-31 00:00:00'
   AND Site = '회룡천1' AND SpeciesKo = '수달';      -- 가드: 값이 다르면 0건 갱신
-- … 838줄
SELECT count(*) FROM Mammal WHERE ObservationSite IS NOT NULL;   -- 838 이어야 함
COMMIT;
```

**방안 선택은 사용자 몫이다. 어떤 방안도 실행하지 않았다.**

### 3-4. 결정 (2026-10-16) — 방안 2 · 형태 (가) SQL 스크립트 · 실행은 사용자

- 생성기: 스크래치 `gen_restore_sql.py` (입력 = §3-1 미리보기 목록 + 게시 DB `mode=ro`).
