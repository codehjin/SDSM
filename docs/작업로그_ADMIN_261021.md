### 2-1. 중복 등록(문제 2·3)

**같은 기록의 기준**
| 분류군 | 기준 | 단위 |
|---|---|---|
| 어류·저서동물·수질·서식수변 | 대분류(파일명 생태현황/방류하천) · 지점 · 연도차수 · 조사일(날짜) | 기록 1건(어류·저서는 부모 + 종 행) |
| 조류·포유류·양서파충류 | 연도차수 · 하천 · 지점 · 조사일(날짜) | 같은 값의 행 묶음 |

- 비교는 지점·하천·연도차수를 공백 제거·대문자로(코드성 값), 조사일은 날짜만. 빈 값은 빈 값끼리 같다(양서 지점 없음 등).
- DB 쪽은 그 분류군 표 전체를 ID·연도차수·지점·조사일(·하천·SiteDivisionId)만 읽어 메모리에서 맞춘다.

**흐름** — [변환된 자료 일괄 저장] → (종전) '자료 n건을 저장하시겠습니까?' [예] → **같은 기록 찾기** → 있으면 기록(묶음)마다 창:

```
어류 — 같은 기록이 DB에 있습니다 (1/1)
새로 저장할 기록 : [방류하천] 곡교천1 · 2024분기4차 · 2024-11-11 · 종 16행
DB에 이미 있는 기록 : 2건 (ID 938, 939) · 종 32행 — [바꾸기]는 모두 지웁니다
[ ] 나머지 같은 기록에도 같게 적용        [건너뛰기] [바꾸기] [추가]
```
- [건너뛰기]가 기본 단추(Enter) · 창을 X 로 닫아도 건너뛰기.
- 저장 뒤 같은 기록이 있었으면 결과 창: `새로 저장 n · 바꿔 저장 n · 건너뜀 n · (같은 기록이 있는데 추가 n)`.
- `SavedFileInfo`(저장 이력)는 실제로 저장·바꾼 것이 있을 때만 남긴다(모두 건너뛰면 남기지 않음).
- 같은 기록을 확인하다 오류가 나면 **저장하지 않고** 멈춘다(`GB.LogWrite` + 오류 창).

**바꾸기 = 한 트랜잭션**
- 어류·저서: 기록마다 `ReplaceSave` — `BeginTransaction` → 옛 종 행 `ExecuteDelete` → 옛 부모 `ExecuteDelete` → 새 부모 `Add`·`SaveChanges`(ID) → 새 종 행 `AddRange`·`SaveChanges` → `Commit`. 실패하면 되돌리고 예외를 올려 저장 실패로 처리.
  (`추가`·새 기록은 종전 경로 그대로: Repository `InsertAsync` + 원시 SQLite 트랜잭션으로 종 행)
- 수질·서식수변·관찰형: 종전부터 **파일 전체가 한 트랜잭션**이다. 그 안에서 바꿀 옛 기록을 먼저 `ExecuteDelete` 하고 새 기록(건너뛴 것 빼고)을 넣는다.

**파일명 경고** — '저장된 기록이 있는 파일명입니다. 계속 진행하시겠습니까?'(OK/Cancel, 기본 취소)를 없애고
알림 '같은 이름의 파일을 저장한 기록이 있습니다(날짜). 같은 기록인지는 저장할 때 내용으로 확인합니다.' 로 바꿨다(멈추지 않음).
식물상·식생·식생환경 3종은 이번 범위 밖이라 종전 경고를 그대로 두었다.
