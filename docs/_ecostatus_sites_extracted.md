포유류 445건 중 좌표가 붙은 기록의 좌표를 펼쳐 보면, 3개 권역 안에서 **수백 m 간격으로 연속**한다

→ **§5 결정 5번(포유류)·1번(양서파충류) 은 "지점을 어떻게 만들까"가 아니라
"이 분류군이 지점 기반이 맞는가"부터 물어야 한다.** 트랜섹트라면 지점 마스터에 억지로 넣기보다
권역 3개만 등록하고 좌표는 기록에 남기는 편이 원자료에 충실하다.

### 8-1. 관찰형 3종도 **정점으로 관리한다** — `IsArea` 기각

> 사용자: **"조사장소는 정점으로 발주처에서 지정한다. 권역과 트랜섹트 조사여도 정점명으로 관리한다."**

- ❌ `IsArea` 필드를 **추가하지 않는다.** §7-6 의 권고는 기각되었다.
- ✅ 조류·포유류·양서파충류도 어류와 **동일하게 정점 지점으로 등록**한다.
- ✅ 지점은 **1지점 = 대표 좌표 1쌍**을 갖는다.

**이 결정이 바꾸는 것 — 지점 목록의 원천이 바뀐다.**

정점을 **발주처(삼성)가 지정**한다면, 지점 마스터의 원천은 조사자료가 아니라 **발주처 지정 문서**다.
지금까지의 추출(§3)은 *조사자가 실제로 적어 낸 값*이라 원천이 아니라 **대조용 참고자료**다.

| | 이전 전제 | **확정 전제** |
|---|---|---|
| 지점 목록 원천 | 조사자료에서 추출 | **발주처 지정 정점 목록** |
| §3 추출 목록의 지위 | 등록할 시드 | **누락·오기 대조용** |
| 좌표 산포(조류 17.8km·포유류 궤적) | 권역 조사라 정상 | **데이터 품질 문제** — 정점 좌표가 아닌 값이 들어간 것 |

**따라서 등록 전에 반드시 필요한 것**

- [ ] **발주처 지정 정점 목록**(분류군별 정점명·좌표·설명)을 확보한다. ← **선행 조건**
- [ ] 확보한 목록과 §3 추출 목록을 대조해 *지정에 없는데 조사된 지점* / *지정됐는데 조사 안 된 지점* 을 뽑는다.
- [ ] 좌표 산포가 큰 조류 15개 지점은 **정점 좌표를 발주처 목록에서 가져온다.** 조사자료 좌표는 쓰지 않는다.

> ⚠ **양서파충류(지점명 0건)는 발주처 목록 없이는 등록이 불가능하다.**
> 조사자료에 지점명이 한 건도 없어 대조할 대상조차 없다. 이 분류군은 발주처 목록 확보가 **유일한 경로**다.

### 8-2. 방류하천과의 이름 충돌 — **`Project` 로만 구분** (`AliasOf` 기각)

> 사용자 선택: **(가) Project로만 구분**

- ❌ `AliasOf` 필드를 **추가하지 않는다.** §7-2 의 (다) 권고는 기각되었다.
- ✅ 생태현황 쪽 **개명도 하지 않는다.** 이름은 각 사업의 관행대로 둔다.
- ✅ `방류하천/오산천1` 과 `생태현황/오산천1` 은 **완전히 별개 지점**으로 취급한다.

**따라서 반드시 지켜야 할 것 — 조사자가 대분류를 잘못 고르면 자료가 조용히 섞인다.**

- [ ] 조사자 앱 지점 드롭다운은 **선택된 `Project` 의 지점만** 보여준다. (섞어서 보여주지 않는다)
- [ ] 조사개황에서 **대분류를 바꾸면 선택된 지점을 즉시 해제**한다. 이전 지점이 남아 있으면 안 된다.
- [ ] 대분류가 선택되지 않은 상태에서는 지점 드롭다운을 **비활성화**한다.
- [ ] 내보내기 엑셀 지점 열은 항상 `Project` 와 함께 기록한다.

> §7-1 의 대응표(오산천5=오산천11 등 15쌍)는 **구현에 쓰지 않는다.**
> 다만 나중에 통합 분석이 필요해질 때를 위해 문서로는 남겨 둔다.

### 8-3. 어류 `진위천1~5` — **연도별 별개 지점**

> 사용자 선택: **연도별 별개 지점**

같은 `SiteName` 이 연도 구간별로 여러 레코드를 갖는다. 즉 지점 식별자가 **`(SiteName, 연도)`** 복합키가 된다.

**필요한 모델 변경** — `SurveySite` 에 유효 연도 구간을 추가한다.

```csharp
/// <summary>이 지점 정의가 유효한 시작 연도. null이면 제한 없음.
/// 같은 SiteName이 연도별로 다른 장소를 가리킬 때 구간을 나눈다(예: 진위천1).</summary>
public int? ValidFrom { get; set; }

/// <summary>이 지점 정의가 유효한 끝 연도(포함). null이면 현재까지.</summary>
public int? ValidTo { get; set; }
```

**조사자 앱 동작**
- 조사개황의 **조사연도로 필터링**해 해당 연도에 유효한 지점 하나만 드롭다운에 띄운다.
- 연도가 아직 입력되지 않았으면 전체를 띄우되 `진위천1 (2023)` 처럼 **구간을 병기**한다.
- ⚠ `SiteName` 자체는 바꾸지 않는다. 조사자료의 `Site` 값과 매칭이 깨지면 안 된다.
