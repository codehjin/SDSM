## 5. 테이블 명세서 자동 생성

### 5.1 근거 두 가지를 맞대어 만든다

| 근거 | 가져오는 것 |
|---|---|
| `SDSM_Models\*.cs` | `[Table]` 표 이름 · 클래스 요약 주석(표 설명) · 속성 이름 · C# 형 · `[Key]` · `[Required]` · `[DisplayName]`(항목명) · `[Description]` · 줄 끝 주석(`//소수점 6자리` · `//필수` · `//빈값없음`). `[NotMapped]` · `[ForeignKey]` 탐색 속성 · `ICollection` 은 뺀다 |
| 시험 DB 사본 `pragma table_info` · `pragma foreign_key_list` | DB 열 이름 · SQLite 형(INTEGER · TEXT · REAL) · NOT NULL · PK · FK |

**시험(이번 A1 · scratchpad)**: `[Table]` 클래스 25개를 읽었고, 주 표 9 + 지점 구분 + 종목록 2 + 식생 4 에서 **모델 속성 ↔ DB 열이 1:1 로 맞는다**(남는 쪽은 `[NotMapped]` · 탐색 속성뿐 · admin6 · 5th 두 사본 같음). `SurveyDate` 는 모델 `[Required]` 이지만 DB 는 NOT NULL 이 아니다 — 필수 칸은 '모델 또는 DB 어느 한쪽'으로 표시하고, 조건부 필수(지점명: 방류하천만 등)는 보충 파일로 적는다.

### 5.2 칸 구성

`No. | 항목명 | 열 이름 | 데이터 타입 | 필수 | KEY | 비고` — v1.0 의 '길이'는 빼고(D2) '열 이름'을 넣는다.
항목명의 줄바꿈(`\n`)은 한 줄로 이어 쓴다(예 '채집 소요시간(분)').

### 5.3 비고를 채우는 규칙

1. 자동: PK → '자동생성' · FK → '→ 표.열' · 계산 칸(총 개체수 · 총 종수 · M1~M7 · FAI 점수/등급 · DI · H′ · R1 · J′ · BMI 점수/등급 · 평가점수/등급 · 수질 등급 8종) → '자동계산'.
2. 주석: '소수점 n자리' → **'화면 소수 n자리'**(저장은 원값 — 2026-10-20 · 21). 위도 · 경도만 '소수 6자리로 저장'.
3. 보충 파일(손으로 관리 · 짧게): 항목명 바꿔 보이기(저서 `FineGravel` → '왕모래(2~16mm)', `BigStone` → '큰돌 이상(>256mm)', `Mud` → '진흙 이하(<0.063mm)' — 모델 `[DisplayName]` 은 엑셀 머리글 키라 그대로 둔다), 2026-10 변경 메모(저서 암반 · 콘크리트 '지침 6칸 밖 · 2026-10 부터 비움 · 값은 특이사항'), 조건부 필수, 코드 값(수피도 1 없음 · 2 부분적 · 3 짙음 등).

- Python 표준 라이브러리(`sqlite3` · `re` · `csv`)만 쓴다.

### 6.2 권장 흐름

```
원고(장별 .md) ─ markdown-it-py ─▶ HTML 한 장 + manual.css(@page A4 · 글꼴 · 표 · 그림 번호)
   ─ Playwright + Edge(page.pdf: A4 · 바닥글 쪽 번호 · outline=True · tagged=True) ─▶ 1차 PDF
   ─ pypdf: 책갈피의 쪽 번호를 읽어 목차에 채움 ─▶ 2차 PDF ─ pypdf: 제목 · 작성자 · 판 ─▶ manual.pdf
```

S1 과 맞추면(§6.4) 두 번째 단계는 Playwright 대신 Chrome/Edge 명령줄 인쇄가 되고, 쪽 번호는 CSS `@page` 로 넣는다. 나머지 흐름은 같다.

**시험(scratchpad · 2쪽)**: Edge 156 에서 PDF 169 KB(그림 1장 97 KB 포함) · 글꼴 `AAAAAA+KoPubWorldDotumMedium` **부분 내장** · h1 두 개가 책갈피 2개(1쪽 · 2쪽)로 · 쪽 번호 바닥글 · 글자 뽑기 · 검색 됨 · JPEG 은 다시 압축하지 않고 그대로 들어감. 고칠 점: 바닥글 숫자가 ArialMT 로 나옴 → 바닥글 틀에 글꼴을 직접 지정.

### 6.3 목차 쪽 번호 — 두 번 굽기

Chromium 은 CSS `target-counter()` 를 지원하지 않아 목차에 쪽 번호를 한 번에 넣을 수 없다. 1차로 구운 PDF 의 책갈피(h1 · h2)에서 쪽 번호를 읽어 목차 HTML 에 넣고 2차로 굽는다. 목차는 2쪽으로 자리를 고정해 1차 · 2차 쪽이 밀리지 않게 한다. 그림 번호('그림 3-5')와 그림 목록은 스크립트가 그림 파일 이름에서 단다.

### 6.4 조사자(S1)와 맞추기

S1 계획 `..\SDSM_Surveyor\docs\manual\계획_조사자설명서.md`(조사자 작업 트리 · **커밋 전** · 2026-10-27 15:15)를 읽기만 했다. 같은 도구(Python · markdown-it-py · pypdf · Chrome/Edge 헤드리스 · 두 번 인쇄)를 쓰고, S1 도 "관리자도 같은 스크립트(글꼴 경로만 인자)"라고 적었다. 다른 곳과 맞춘 안:

| 항목 | S1(조사자) | A1(이 문서) | 맞춘 안 |

| 작은 창 · 잘라낸 그림 | 원래 크기 | JPEG 품질 80 | 10~20 KB |

- PNG 를 그대로 넣지 않는다 — PNG 는 PDF 안에서 다시 풀려 커질 수 있고, JPEG 는 그대로 들어간다(§6.2 시험).
- 글꼴은 2벌만(본문 Medium · 제목 Bold) — 부분 내장이라 합쳐 0.1~0.2 MB.
- **예상(필수 52장)**: 화면 그림 약 32장 × 50 KB(표가 빽빽한 목록 약 67 · 듬성한 화면 약 36 의 평균) ≈ 1.6 MB + 지도 3장 × 130 KB ≈ 0.4 MB + 작은 그림 약 17장 × 15 KB ≈ 0.25 MB + 글꼴 · 글 ≈ 0.2 MB = **약 2.5 MB**. 선택 7장까지 넣으면 약 2.8 MB.
- 폭 1400px 로 하면 같은 그림이 약 2.9~3.2 MB 라 목표에 빠듯하다.
- 3.0 MB 를 넘으면 이 순서로 줄인다: ① 품질 70 ② (선택) 그림 빼기 ③ 화면 그림 폭 1100px.
