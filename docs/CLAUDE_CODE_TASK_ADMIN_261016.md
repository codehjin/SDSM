## 2. 확정 사실 (2026-10-16 확인)

**포유류 양식 `포유류` 시트 (방류하천 곡교천·오산천판 모두 같음)**

| 열 (0-based) | 머리글 | 자료 행 |
|---|---|---|
| P (15) | 위도 | 값 |
| Q (16) | 경도 | 값 |
| R (17) | `이후 내용 가능한 범위` (안내 글) | **비어 있음** |
| S (18) | **관찰지 유형** (①산림… 중 택) | **값 있음** (수계·하천·초지 등) |
| T (19) ~ | 확인/흔적 유형 (포획·관찰·울음…) | 값 |

- 관리자 Import는 관찰지유형을 **17(R)** 에서 읽는다. 흔적(Trace1)은 19(T)로 맞다.
- 그 결과 **게시 DB `Mammal` 1,107건 전부 `ObservationSite`가 NULL**이다.
- 조사자 앱은 다음 작업부터 관찰지유형을 양식대로 **S열**에 쓴다. 다만 이미 배포된 조사자 테스트판은 R열에 썼다(테스트 자료뿐).

**수질 (참고 — A-2에서 확인)**
- 관리자는 수질 확장항목을 C+D열 글자로 찾는다.
- 최종본 수질 양식에는 **수심 행이 없다.** 그래서 양식 그대로 낸 파일에서는 수심을 읽을 수 없다.
- 조사자 앱은 양식의 `지속 삽입 가능` 행 아래에 수심 행을 덧붙인다. 관리자 검색이 이 행을 찾는지 A-2에서 확인한다.

## 3. A-1 — 포유류 관찰지유형 읽기 열 수정

- `ObservationSite`를 **18(S)** 에서 읽는다.
- **S가 비어 있으면 17(R)을 읽는다.** 조사자 테스트판이 R에 쓴 파일과 호환하기 위해서다. 최종본 양식의 R열 자료 칸은 비어 있으므로 부작용이 없다.
- 같은 메서드의 다른 열(위경도 9~16, Trace1~12 = 19~30, 조사자 31, 비고 32)도 양식 머리글과 맞는지 함께 확인한다. 어긋난 것은 고치지 말고 A-2 표에 넣는다.
- **시험**
  - 최종본 포유류 파일 4개(방류하천 곡교천·오산천·원천리천, 생태현황)를 Import 변환까지만 돌려 관찰지유형이 채워지는지 건수로 확인한다. **저장(DB 쓰기)은 하지 않는다.**
  - 자동으로 돌릴 수 있으면 하네스로, 없으면 변환 함수를 직접 호출하는 시험 코드로 한다(시험 코드는 저장소에 남기지 않거나 `tools\` 아래에 둔다).
- 빌드 경고·오류 0.

## 4. A-2 — 일괄등록 Import 좌표 전수 대조 (읽기·보고만)

- 7개 분류군(어류·저서동물·조류·포유류·양서파충류·수질·서식수변)마다 Import가 읽는 셀 좌표를 최종본 양식의 머리글·라벨과 실자료 위치에 맞춰 본다.
- 양식이 방류하천판·생태현황판으로 나뉘면 둘 다 본다.
- 게시 DB에서 영향을 건수로 확인한다(해당 칼럼이 전부 NULL이거나 엉뚱한 값인 건수).
- 보고 표 형식:

  | 분류군 | 항목 | 관리자 좌표 | 양식 좌표 | 일치 | 게시 DB 영향 건수 | 비고 |
  |---|---|---|---|---|---|---|

- 수질 수심: 조사자 앱처럼 `지속 삽입 가능` 아래에 수심 행을 덧붙였을 때 관리자 검색이 찾는지 확인한다.
- 코드표(날씨·범람원·하천유형·흐름상태 등)의 글자가 양식 정의와 다른 것(예: `산강형`)도 표에 넣는다.

## 5. A-3 — 포유류 1,107건 관찰지유형 복구 방안 조사 (DB 쓰기 금지)

- 게시 DB의 `Mammal` 행을 최종본 파일의 자료 행과 1:1로 짝지을 수 있는지 본다.
  - 후보 키: 연도차수·지점명·조사일·국명·위경도·행 순서 등
  - **매칭률**(유일하게 짝지어지는 건수 / 1,107)을 낸다.
- 다음 방안을 비교해 장단점과 위험을 표로 보고한다.
  1. 포유류 자료를 지우고 최종본 파일로 다시 일괄등록
  2. 관찰지유형만 채우는 일회성 갱신 도구
  3. 기존 자료는 두고 앞으로의 일괄등록부터 반영
- 발주처에 배포된 DB에도 같은 조치가 필요하다. 사용자가 실행할 수 있는 형태(관리자 앱 기능 / 별도 도구 / SQL 스크립트)를 함께 제안한다.
- **방안 선택은 사용자가 한다.** 어떤 방안도 실행하지 않는다.
