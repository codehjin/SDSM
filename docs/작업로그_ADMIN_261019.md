## 1. 단계

```
.\tools\publish.ps1              배포본 만들기(0~4단계)
.\tools\publish.ps1 -CheckOnly   1~3단계 검사만(압축·배포 폴더를 만들지 않음)
tools\publish.cmd [-CheckOnly]   탐색기에서 두 번 눌러 실행(위와 같음)
```

| 단계 | 하는 일 | 멈추는 조건(종료 코드) |
|---|---|---|
| 0 커밋 확인 | `git status --porcelain` · 브랜치·커밋 표시 | 미커밋 변경이 있으면 멈춤(5). `-CheckOnly` 는 경고만 하고 계속. 이 저장소에서 띄운 관리자 앱이 떠 있으면 멈춤(9) |
| 1 빌드 | `dotnet build SDSM.sln -c Release --no-incremental` · 경고·오류를 `tools\_publish_log\build_warnings.log`·`build_errors.log` 로 따로 받아 센다 | 오류 1건 이상 또는 **경고 1건 이상**(1) |
| 2 게시 | `dotnet publish SDSM_App\SDSM_App.csproj -c Release -r win-x64 --self-contained true -p:DebugType=none -p:DebugSymbols=false -o tools\_publish` | 게시 실패(2) |
| 3 내용 확인 | 아래 표 | 하나라도 어긋나면(3) |
| 4 압축 | `...\samsung\7_보낸파일\yyyy-MM-dd\DB통합SW_yyMMdd.zip` (압축 안 맨 위 폴더도 `DB통합SW_yyMMdd\`) | 보낼 폴더 없음·압축 실패(4) |

**3단계 내용 확인**

| 확인 | 내용 |
|---|---|
| 실행 파일 이름 | `SDSM_App.exe` → **`삼성DS모니터링DB통합관리프로그램.exe`** (03-05 배포본과 같은 이름 → 바로가기 유지) |
| 필수 파일 8개 | 위 exe · `SDSM_App.dll` · `SDSM_Core.dll` · `SDSM_Models.dll` · `SDSM_App.dll.config` · `SDSM_App.runtimeconfig.json` · `SDSM_App.deps.json` · `sites.json` |
| 섞이면 안 되는 것 | 확장자 `.sqlite`(·`-wal`·`-shm`·`-journal`) 파일이 하나라도 있으면 멈춤 · 맨 위 `mbtiles\` 폴더가 있으면 멈춤 |
| sites.json | 프로젝트 `SDSM_App\sites.json` 과 SHA-256 같은지 · 버전과 지점 수가 읽히는지 |
| Telerik 판 | `Telerik.Windows.Controls.dll` 파일 버전이 `2026.2.520` 으로 시작하는지 |
| 표시만 | .NET 런타임 판 · exe 제품 버전(커밋 해시 포함) · 파일 수·용량 |

정한 것과 이유:
- **1단계 = 빌드 경고 0.** 관리자에는 조사자의 `xaml_audit.py`·`contrast_audit.py` 같은 정적 검사 도구가 없다. `--no-incremental` 은 필수다 — 증분 빌드는 이미 컴파일한 파일의 경고를 다시 내지 않아 "경고 0" 이 거짓이 된다.
  경고 집계는 MSBuild 파일 기록기(`-flp1:...;warningsonly` · `-flp2:...;errorsonly`)로 받는다. 한글 MSBuild 의 화면 요약(`경고 0개`)을 글자로 읽지 않기 위해서다.
  경고 0 이면 파일에는 BOM 3바이트만 남는다. 스크래치의 빈 콘솔 프로젝트에 CS0168 경고를 하나 일부러 넣어 보니 1줄로 잡혔다.
- **exe 이름만 바꿔도 실행된다.** .NET apphost 는 `SDSM_App.dll`·`SDSM_App.runtimeconfig.json` 을 파일 이름으로 찾고 exe 이름과는 상관없다. 중복 실행 방지 Mutex 이름도 `"SDSM_App"` 고정이다(`App.xaml.cs:60`). 03-05 배포본도 같은 방식으로 이름을 바꿔 보냈다.
  그래서 runtimeconfig·deps 두 파일도 필수 목록에 넣었다.
- **0단계에서 멈추는 이유가 관리자에도 그대로 있다.** 게시한 exe 의 제품 버전에 커밋 해시가 박힌다(`1.0.0+025e9bb…` — .NET SDK 기본 동작). 미커밋 상태로 압축하면 해시와 압축 내용이 어긋난다.
- **실행 중 확인은 경로로 거른다.** 조사자 스크립트는 프로세스 이름만 보지만, 관리자는 개발 PC 에서 설치본·본 checkout 의 `bin\Debug` 를 띄워 둔 채 게시할 수 있다. 이 저장소 폴더 아래에서 띄운 `SDSM_App`·`삼성DS모니터링DB통합관리프로그램` 만 막는다.
- **보낼 폴더는 조사자와 같은 `...\samsung\7_보낸파일\yyyy-MM-dd\`.** worktree 에서 실행해도 같은 곳으로 가도록 `git rev-parse --git-common-dir` 의 부모(본 저장소)에서 `..\..\7_보낸파일` 을 찾는다.
  이름은 03-05 배포본 `DB통합SW_260305` 과 같은 꼴로 `DB통합SW_yyMMdd`. 압축은 조사자와 같이 `ZipFile.CreateFromDirectory`(파일 이름 UTF-8 — exe 이름이 한글이다).
- 게시 설정은 VS 게시 프로필 `FolderProfile.pubxml`(Release · win-x64 · 단독 실행형 · 단일 파일 아님 · ReadyToRun 아님)과 같다. 출력 경로만 이 PC 에 없는 `D:\1_Tasks\8_삼성DS\3_publish` 대신 `tools\_publish`.
- 압축이 끝나면 "설치 폴더에 덮어쓰기 · `SDSMDB.sqlite`·`mbtiles\` 는 압축에 없음 · 덮어쓰기 전에 `SDSMDB.sqlite`·`sites.json` 백업"을 화면에 띄운다(`작업로그_ADMIN_261020.md` §7 ①·③).

## 2. 파일

| 파일 | 내용 |
|---|---|
| `tools\publish.ps1` (새) | 위 0~4단계. **UTF-8 with BOM**(없으면 Windows PowerShell 5.1 이 한글을 CP949 로 읽어 깨진다). 한글이 들어가는 일은 전부 여기서 한다 |
| `tools\publish.cmd` (새) | `powershell -NoProfile -ExecutionPolicy Bypass -File "%~dp0publish.ps1" %*` 한 줄. **ASCII 만**·CRLF. 인자를 그대로 넘기므로 `publish.cmd -CheckOnly` 도 된다 |
| `.gitignore` | `tools/_publish/` · `tools/_publish_zip/` · `tools/_publish_log/` 추가 (기존 `publish/` 줄은 `_publish` 에 걸리지 않는다) |
| `.gitattributes` | `*.cmd`·`*.bat` 을 `eol=crlf` 로 — 조사자 저장소와 같은 줄. 관리자는 `* text=auto eol=lf` 만 있어서 .cmd 가 LF 로 체크아웃될 뻔했다 |

조사자 스크립트와 다른 점: `-Test`(예시 자료) 없음 · 1단계가 정적 검사 대신 빌드 · 3단계 확인 항목 · exe 이름 변경 · 압축 이름 ·
`Read-Host` 를 try 로 감쌌다(자동 실행처럼 입력을 받을 수 없을 때 대기 대신 그냥 끝나도록. 실패 시 종료 코드는 그대로).

## 3. 시험 — `-CheckOnly`

이 worktree(`claude/clever-ptolemy-351e00`, master 025e9bb 기준)에는 `SDSM_App\sites.json` 과 csproj `Content` 줄이 **없다**.
둘 다 `claude/admin-release-261020` worktree 에 미커밋으로만 있다(`작업로그_ADMIN_261020.md` §3-2).

| 회 | 조건 | 결과 |
|---|---|---|
| 1 | 그대로(sites.json 없음) | 0 경고(미커밋 4건) · 1 **경고 0·오류 0** · 2 게시 성공 · 3 exe 이름 변경 후 **`필수 파일 누락 : sites.json` 으로 멈춤(종료 코드 3)** — 확인 장치가 동작함 |

| 3 | 2와 같음 · 고친 스크립트 | **1~3단계 통과 · 종료 코드 0** (아래) |

```

    필수 파일 8개 확인
```

- 압축·배포 폴더: `tools\_publish_zip\` 생기지 않음 · `F:\desktopSW\samsung\7_보낸파일` 목록 실행 전후 같음.
- 게시본 `*.pdb` 0개(`-p:DebugType=none` 적용). 261020 §5-2 수동 게시본에는 pdb 가 있었다.
- 파일 744개는 하위 폴더(위성 어셈블리 언어 폴더 등)를 포함한 수다. 맨 위 폴더만 세면 449개.
- 시험 뒤 얹었던 두 가지는 되돌렸다(`git checkout -- SDSM_App/SDSM_App.csproj` · `SDSM_App\sites.json` 삭제).
  얹은 sites.json 은 261020 worktree 의 것을 그대로 복사했다(SHA-256 `7434142c…` 같음).
- 앱 실행 시험은 하지 않았다 — 게시 폴더에 DB 가 없어 실행하면 그 자리에 DB 를 새로 만들 수 있다. exe 이름 변경 방식은 03-05 배포본이 이미 썼다.
- ⚠ 남은 것: `tools\_publish\`(약 460MB, 4회 게시본 — sites.json 없음. 실행 때마다 지우고 새로 만든다) · `tools\_publish_log\` · 각 프로젝트 `bin\Release`·`obj`. 모두 .gitignore 대상이다. 지워도 된다.
- 콘솔 출력 참고: 시험은 출력을 파일로 받아서 PowerShell 출력이 CP949 로 기록됐다(`—` 가 `?` 로 보임). 창에서 실행하면 `chcp 65001` 로 바르게 보인다(조사자 스크립트와 같다).

### 3-1. publish.cmd

4회(`cmd /c tools\publish.cmd -CheckOnly`, sites.json 없는 상태): 머리줄 `=== SDSM 관리자 앱 검사만(-CheckOnly) ===` → 1·2단계 통과 →
3단계 `필수 파일 누락 : sites.json` 으로 멈추고 **종료 코드 3 이 cmd 밖으로 그대로 나왔다.** 인자 전달·한글 출력 모두 정상(.cmd 는 ASCII).

## 4. 병합 순서 — ⚠ 이 브랜치만으로는 `-CheckOnly` 가 3단계에서 멈춘다

`sites.json` 이 필수 파일이므로 **`claude/admin-release-261020` 의 `SDSM_App\sites.json` + csproj `Content` 가 함께 들어가야** 통과한다.
두 브랜치는 같은 파일을 고치지 않는다(이 브랜치: `tools\publish.*` · `.gitignore` · `.gitattributes` · 이 문서). 순서는 상관없다.
병합 뒤 본 checkout 에서 `.\tools\publish.ps1 -CheckOnly` 를 한 번 돌려 3회와 같은 결과가 나오는지 본다.

## 5. 발주처 배포 때

`작업로그_ADMIN_261020.md` §7 ① 의 2·3번(게시 · exe 이름 변경)을 이 스크립트가 대신한다:

1. 모든 변경을 커밋한다 → `tools\publish.cmd` 를 두 번 누르거나 `.\tools\publish.ps1`.
2. `7_보낸파일\yyyy-MM-dd\DB통합SW_yyMMdd.zip` 이 생긴다. 압축을 풀면 `DB통합SW_yyMMdd\` 폴더 하나.
3. 발주처: 앱을 닫고 설치 폴더를 백업(`SDSMDB.sqlite` · `mbtiles\` · 있으면 `sites.json`) → 폴더 **안의 내용**을 설치 폴더에 덮어쓴다.
